# RhymeTrace · 韵部探索器

大学生大创项目《从韵书到诗歌：基于〈佩文韵府〉的历代用韵选择研究与可视化平台构建》。以三江、四支为例，建设可追溯的韵书资料查询平台。

> 更新：2026-11-02。**当前先完成三江、四支的专题字表，以及字、词、典故和引文的基础查询。** 复杂的诗歌用韵统计、诗人偏好和扩大覆盖范围暂缓，任务保留在[阶段范围与待办](Research/阶段范围与待办-2026-11-02.md)。这项决定更新了 10-06 交接文档中的阶段排序。

## 当前能做什么

- 输入字、词语或韵部名，在搜索框下方切换“字条目 / 全文检索”（韵部名显示“韵部条目”）；支持 OpenCC 覆盖的简繁检索，“窗”可查询原字“窓”。未确认的异体关系不自动归并。
- 查看字头的反切与释义原文，以及三江、四支的完整收录字表。原字形保留，重出字分别展示。
- 检索词语、典故相关引文，按韵部和韵藻/增补/对语/摘句筛选，分页查看。
- 从资料记录回到字条目、本字原文和源文件行号，核对上下文。

“典故查询”目前指查阅韵书词条和引文，不生成新的典故解释，也不推断作者、朝代、诗题或实际押韵关系。

## 打开与使用

直接双击 HTML 即可离线使用，无需安装前端依赖或启动后端。

| 页面 | 用途 |
| --- | --- |
| [entry.html](entry.html) | 当前基础功能入口。查“江”“枝”“诗”“三江”“四支”，可切换条目与全文结果 |
| [sources.html](sources.html) | 字表浏览、词语/引文检索、类型筛选、分页和本字原文 |
| [index.html](index.html) | 保留原大厅布局；字块和单字搜索跳转真实资料条目。大厅分布图、摘要、频次与诗歌卡仍是旧演示数据 |
| [annotate.html](annotate.html) | 已有的内部人工标注工具，当前阶段暂缓采集诗歌标注 |
| [demo.html](demo.html) | 后续对比视图、诗人条目、数据卡的概念演示；数字全部为示意 |

示例：[字条目·江](entry.html?char=江)、[韵部·四支](entry.html?rhyme=四支)、[引文·春江](sources.html?q=春江)。检索支持词条与引文中的连续关键词；不带条件时按源文件顺序浏览。

搜索框下方提供横向的“字条目 / 全文检索”切换栏，共用已提交的查询词；查询“三江 / 四支”时，第一项显示“韵部条目”。首次查询默认显示已收录的字或韵部条目，没有对应条目的词语默认显示全文结果。选定视图后，再次搜索保留该视图；没有字条目时仍保留两个标签，并提示“暂无条目”，可切换查看空状态。

切到“全文检索”会搜索整个资料库中出现该关键词的记录，不局限于该字头下的内容；随后可以按韵部/类型筛选。切换视图时重新使用全库范围。全文链接使用 `mode=fulltext`，分页保留关键词、模式与筛选条件；浏览器前进、后退可返回此前的结果。已有的字表、本字资料与原文详情入口继续保留。

开发时可运行：

```powershell
python scripts/serve.py
```

打开 [http://127.0.0.1:8123](http://127.0.0.1:8123)。服务器带 no-store 头；可用 `python scripts/serve.py 8124` 更换端口。

## 资料库现状与边界

当前底稿为师姐提供的 `Database/3江韵4支韵_级联测试.md`。原始文件未修改，已抽取为可重建的结构化 JSON，并生成支持离线网页的 JS 数据包。

| 范围 | 抽取结果 |
| --- | --- |
| 三江 | 46 个字条、46 种原字形 |
| 四支 | 443 个字条、437 种原字形，六组同字重出分别保留 |
| 合计 | 489 个字条、17,724 条资料记录 |
| 资料类型 | 韵藻 2,701 条、增补 12,531 条、对语 1,229 条、摘句 1,263 条 |

**以上是所提供文件的抽取数量，不是已经校定的全部可用韵字数、独立诗歌数或历史用韵次数。** 条目和引文统一标为待核验；源文件的完整性、底本版本、整理来源及使用说明仍待补充。

- 反切、释义、异读/跨韵说明、`丨` 代字、`?` / `□`、罕见字和原文缩进保留，不自动补字或现代化改写。
- 每条记录有卷段和源文件行号；行号不是原书页码。小韵、现代读音和人工校对结论不从文本猜测生成。
- 对语、摘句和韵书引文可作查阅材料，不能直接作为真实诗歌押韵统计。
- 抽取检查报告列出标题缺序号、缺词头与不确定字符，详见 `Database/processed/dictionary-audit.json`。
- “测一问”的旧演示题池仍保存在 `assets/js/entry-data.js`；当前资料条目不加载待核验题池，正式题目待资料核验后再接。

其他已有材料：`Database/chinese-poetry-master/chinese-poetry-master/` 为繁体主诗歌语料候选库，含 MIT 许可证；`Database/cnpoems-master（参考用）/` 仅作术语参考；《佩文韵府校对手册.pdf》指导校对，不能替代原书。`Database/opencc/` 为 Apache-2.0 简繁字符表，仅用于检索归一，不替代研究判定。

## 数据重建与验证

在项目根目录运行：

```powershell
python scripts/build-dictionary.py
python scripts/check-dictionary.py
```

生成物与字段约定见 [结构化资料说明](Database/processed/README.md)：

- `Database/processed/dictionary.json`：字条、反切释义、子记录、原文及行号。
- `Database/processed/dictionary-audit.json`：源文件指纹、数量和待核对问题。
- `assets/js/dictionary-data.js`：同内容离线前端数据包。

检查脚本逐条核对源文件指纹、原文、行号、字条边界和所有正文内容的覆盖；它验证抽取完整性，不代表学术校对完成。不要直接修改生成物。

可用已安装的 Playwright 与 Edge 运行离线浏览器检查：

```powershell
node scripts/check-dictionary-ui.cjs
node scripts/check-query-routing.cjs
```

若 Playwright 不在本地模块搜索路径，可在命令末尾附上包含它的目录；普通网页使用不需要这些测试依赖。

简繁工具仍可使用 `python scripts/lookup.py 詩 雙` 和 `python scripts/gen-charmaps.py`，生成物 `assets/js/charmaps.js` 勿手改。

## 协作纪律与文档

大厅保持既有布局，查询使用独立词典条目；长内容使用摘要和详情链接。AI 不判定韵脚、不生成研究结论，资料事实与可能解释分开。保留已确认文案，不增加积分、排行、计时等游戏化元素。内部跳转使用 `app.navigate()`，长期资源不放 `tmp/`。
